# Как агенту работать с тикетами (вставить в CLAUDE.md проекта)

Скопируй блок ниже в `CLAUDE.md` того проекта, где работает агент-разработчик. Он описывает правила так, чтобы
агент **не сканировал доску** и включался только когда его позвали.

---

## QA-тикеты (tester-huester)

Тикеты этого проекта живут в tester-huester и доступны через MCP-сервер `tester-huester`.

**Не опрашивай доску по своей инициативе.** Не вызывай `list_reports` «на всякий случай» и не перечитывай
тикеты, чтобы узнать, изменилось ли что-то. Владелец сам скажет, когда пора.

### Когда владелец говорит «глянь тикеты» / «что нового»

1. `get_updates` — вернёт **только изменения** с прошлого раза: id тикета, что произошло (`created`,
   `status`, `edited`, `comment`, `archived`, `moved`), кто это сделал и краткое описание. Ничего не
   изменилось — вернётся пустой список, на этом всё.
2. По каждому нужному id: `get_report` (заметка, скриншот, статус, тип, важность **и вся переписка**) и
   `get_repro_steps` (нумерованные шаги, ошибки консоли, упавшие запросы, окружение).
3. Сделай работу.
4. `set_status` — закрывая тикет, **сразу передаёшь доказательство** (см. следующий раздел). Комментарий
   пишется тем же вызовом, отдельный `add_comment` для этого не нужен.
5. `ack_updates` с `cursor` из шага 1 — **только после того, как всё сделано**. Если упадёшь до этого, те же
   события придут снова и ничего не потеряется.

### Закрыть тикет = приложить проверку (правило сервера, не пожелание)

`set_status` с `fixed` **отклоняется**, если не переданы `comment` и `verifyUrl`. Это не совет — это ответ
`400` от коллектора. Причина простая: «fixed» без ссылки перекладывает поиск на владельца — какая страница,
какое состояние, что вообще смотреть.

| Поле | Когда обязательно | Что писать |
|---|---|---|
| `comment` | `fixed`, `wontfix` | что было причиной, что изменено, в каком коммите |
| `verifyUrl` | `fixed` | **абсолютная http(s) ссылка**, открывающая именно тот экран. Не корень сайта — как можно глубже |
| `verifySteps` | когда по ссылке не видно сразу | короткие шаги: «1. открыть заказ 5605 · 2. навести на строку · 3. попап показывает даты» |

Пример правильного закрытия:

```
set_status(id="cd75bb62", status="fixed",
  comment="Попап всплывал на всей строке, потому что hover висел на <tr>. Перевесил на ячейку статуса, добавил задержку 300 мс. Коммит a1b2c3d.",
  verifyUrl="https://erental.ihor.work/staff/orders",
  verifySteps=["Открыть список заказов", "Провести курсором по строке 5605 — попапа быть не должно", "Навести на сам бейдж статуса — попап появляется через 0.3 с"])
```

Владелец видит это на тикете отдельным блоком **«✅ Как проверить»** с кнопкой в один клик.
Если проверять реально нечего (правка невидима в UI) — статус `fixed` всё равно требует ссылку: дай ту
страницу, где поведение наблюдаемо, и объясни в `comment`, почему глазами не видно.

### Статусы — договорённость

| Статус | Значение | Что обязано быть |
|---|---|---|
| `new` | владелец завёл, ты ещё не смотрел | — |
| `triaged` | **взято в работу** — ты внутри задачи | — |
| `fixed` | сделано | `comment` + `verifyUrl` (+ `verifySteps` по необходимости) |
| `wontfix` | не делаем | `comment` с причиной |

Владелец отвечает тебе комментарием в том же тикете — это и есть его поручения («поправь заголовок на
карточке»). Ты увидишь их в `get_updates` как событие `comment` от `human` и в `get_report`.

### Чего делать не нужно

- Не архивируй и не удаляй тикеты — это делает владелец.
- Не трогай тикеты вне своего проекта: ключ ограничен одним проектом, чужие вернут «не найдено».
- Не меняй статус молча — сервер и не даст: `fixed`/`wontfix` без объяснения отклоняются.
- Не подставляй в `verifyUrl` корень сайта, чтобы «пройти проверку». Ссылка должна открывать тот самый экран.

## Что отправить агенту один раз

Если MCP ещё не подключён — конфиг (ключ проекта берётся на дашборде, полоса **projects → agent**):

```bash
claude mcp add tester-huester -s user \
  -e TH_COLLECTOR=https://qa.ihor.work \
  -e TH_PROJECT_KEY=<AGENT_КЛЮЧ_ПРОЕКТА> \
  -- pnpm -C "C:/Users/iphot/Desktop/tester-huester" --filter @th/mcp remote
```

После добавления или обновления **перезапусти приложение агента** — MCP-серверы читаются при старте, иначе
новых инструментов (`get_updates`, `ack_updates`, `add_comment`, `list_comments`) он не увидит.
