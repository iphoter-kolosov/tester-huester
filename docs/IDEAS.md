# Отложенные идеи

Не выброшено — просто не сейчас. Каждый пункт: зачем, что даёт, во что обойдётся.

## 1. Автозапуск агента по событию (диспетчер)

**Идея.** Небольшой скрипт на рабочей машине висит на `GET /api/updates?wait=55` (исходящее соединение, работает
за NAT — входящий вебхук туда не достучится) и запускает Claude Code в headless-режиме `claude -p "…"` только
когда реально пришло событие. В простое — ноль расходов, реакция в пределах секунды.

**Что нужно решить перед реализацией:** объём полномочий. Либо агент правит и коммитит сам (быстро, но без
тормозов), либо работает в отдельной ветке и отдаёт изменения на просмотр.

**Оценка:** ~0.5 дня вместе с автозапуском при старте системы и журналом того, что агент делал.

**Пока вместо этого:** владелец сам говорит агенту, когда заглянуть в тикеты (см. `docs/AGENT-WORKFLOW.md`).

## 2. Встраиваемый виджет + мобильные версии

**Идея.** Тег `script` на сайт клиента вместо расширения. Закрывает три вещи сразу: тестирование на телефоне
(расширения там не работают в принципе), брендированный канал для агентств, и фидбек от заказчика без установки
чего-либо. Ядро (аннотатор, сбор контекста, репро-бандл) уже framework-agnostic и переиспользуется почти целиком;
отличается только способ снять скриншот — в виджете DOM рендерится в картинку.

**Оценка:** 2–3 дня.

## 3. White-label для веб-студий

**Идея.** Тот же виджет под брендом студии (логотип, цвет, свой домен) — у студий клиенты и так шлют баги в
мессенджеры. Ниша специализированных white-label решений в bug reporting пустая.

**Оценка:** +1 день поверх виджета (плюс мультитенантность, если продавать наружу).
